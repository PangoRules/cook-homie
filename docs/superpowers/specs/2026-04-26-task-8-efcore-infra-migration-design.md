# Task 8: EF Core Infrastructure + Initial Migration Design

**Date:** 2026-04-26  
**Status:** Approved  
**Scope:** Expand domain to full v1 model, wire EF Core + AppDbContext, generate single `InitialCreate` migration (tables + PK/FK only), add infra tests.

## Decisions Made

- **Model scope:** Full v1 data model as per `docs/02-DataModel.md` (InventoryItem, Recipe, RecipeIngredient, ShoppingItem).
- **Migration approach:** Single `InitialCreate` covering tables, primary keys, foreign keys, required/nullable constraints. No extra indexes or check constraints at this stage; iteration via follow-up migrations if needed.
- **Test strategy:** Create `CookHomie.Infrastructure.Tests` with integration-style tests against real EF Core provider (PostgreSQL preferred, SQLite fallback).
- **Repository pattern:** Thin repository implementing `IInventoryRepository`; persistence logic belongs to infra layer, business logic remains in application.
- **Branch name:** `feat/add-efcore-infra-initial-migration`

## Architecture & Boundaries

### Domain Layer Expansion
- `InventoryItem`, `Recipe`, `RecipeIngredient`, `ShoppingItem` fully defined with v1 fields.
- All IDs remain `Guid` (UUID).
- `Recipe.Tags` remains `string[]` for PostgreSQL `text[]` mapping.
- `RecipeIngredient.IngredientName` stays text (no FK), preserving fuzzy-match design.
- `ShoppingItem.LinkedRecipeId` nullable FK to Recipe.
- Timestamps (`CreatedAt`, `UpdatedAt`) on entities that require them.

### Infrastructure Layer
- **AppDbContext:** EF Core DbContext with `DbSet<>` for all four entities. Minimal fluent configuration for table names, keys, nullability, and array mapping.
- **InventoryRepository:** Implements `IInventoryRepository`; persists items via EF + SaveChangesAsync.
- **Migrations:** Single `InitialCreate` generated by `dotnet ef migrations add`. Schema covers tables, PK, FK, and required/nullable only.

### Application & WebApi Layers
- Application use case behavior unchanged (still calls `IInventoryRepository.AddAsync`).
- WebApi DI wiring: registers `AppDbContext` and `IInventoryRepository` implementation.
- Connection string read from appsettings at startup; fail fast if missing.

### Test Boundary
- **CookHomie.Infrastructure.Tests:** Integration tests validating repository persistence + FK constraints.
- No mocking of DbContext; uses real provider for behavior verification.

## Success Definition

- All four v1 entities exist in domain with correct field shapes.
- `InitialCreate` migration applies cleanly to empty PostgreSQL database.
- `InventoryRepository` passes persistence and FK integrity tests.
- WebApi startup succeeds with valid connection string.
- Solution builds clean: `dotnet build src/CookHomie.Api/CookHomie.sln` ✓
- All tests pass: `dotnet test src/CookHomie.Api/CookHomie.sln` ✓
